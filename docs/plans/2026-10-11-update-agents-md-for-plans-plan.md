# AGENTS.md への作業計画記録ルールの追加計画

## 目的

エージェントが作業を行う際に `docs/plans/` 配下に作業計画（記録）を残すルールを `AGENTS.md` に追記し、開発・運用の標準化を図る。

## 現状

- `docs/plans/` ディレクトリが存在し、既存例として `2026-10-11-add-healthz-plan.md` が配置されている。
- `AGENTS.md` には作業計画ファイルの作成手順、ファイル命名規則、構成フォーマットに関する明確な記述がない。

## 方針

1. `AGENTS.md` の「コード変更時の推奨手順」セクション（または計画立案に関する冒頭手順）に、作業計画の記録に関するルールを追加する。
2. ファイル命名規則を `docs/plans/<作業日>-<概要>-plan.md`（例: `2026-10-11-add-healthz-plan.md`）として明記する。
3. 計画書作成のタイミングや運用（計画書ファイルのみを先行してPR化・マージする場合と、実装までまとめて行う場合の両方があること）について言及する。
4. 計画書の推奨構成（目的、現状、方針、受け入れ条件、実装・確認手順、対象外など）を記載・例示する。

## 受け入れ条件

- `AGENTS.md` に `docs/plans/<作業日>-<概要>-plan.md` 形式で作業計画を保存する手順・ルールが明記されていること。
- 命名規則および既存の計画書（`2026-10-11-add-healthz-plan.md`）に基づくフォーマット例が含まれていること。
- リントチェック（`tox -e lint` など）がパスすること。

## 実装・確認手順

1. 本計画書 `docs/plans/2026-10-11-update-agents-md-for-plans-plan.md` を作成する。
2. `AGENTS.md` の該当セクション（「コード変更時の推奨手順」等）を編集する。
3. 変更内容を確認し、`tox -e lint` や関連確認スクリプトを実行する。
